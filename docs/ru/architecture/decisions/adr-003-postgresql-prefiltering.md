# ADR-003: Предварительная фильтрация в PostgreSQL для гибридного поиска

## Статус
Отклонено

## Контекст
При выполнении гибридных запросов (семантический поиск + структурированные фильтры) рассматривалась альтернатива выполнению всего внутри Qdrant: сначала запустить структурированный фильтр в PostgreSQL, чтобы получить подмножество идентификаторов подходящих встреч/чанков, а затем передать эти идентификаторы в Qdrant для этапа сравнения векторов.

Предполагалось, что PostgreSQL может обрабатывать большие объёмы структурированных данных эффективнее, чем индекс payload в Qdrant, потенциально уменьшая количество векторов для сканирования и тем самым улучшая общее время отклика.

## Решение
Реализовать двухэтапный процесс поиска:
1. **PostgreSQL** фильтрует встречи/чанки по дате, спикеру и другим структурированным метаданным, возвращая разрешённые идентификаторы.
2. **Qdrant** выполняет поиск по векторному сходству, ограниченный этими идентификаторами.

## Последствия
- **Положительные**:  
  PostgreSQL хорошо оптимизирован для сложной реляционной фильтрации на массивных таблицах, что теоретически может быстрее сужать пространство поиска, чем фильтры payload в Qdrant для определённых шаблонов запросов.
- **Отрицательные** (причина отклонения):  
  Подход добавляет как минимум один лишний сетевой цикл (API → PostgreSQL → API → Qdrant).  
  Он переносит сложность на уровень приложения, требуя от API объединения двух отдельных запросов.  
  На практике фильтрация на основе payload в Qdrant выполняет весь гибридный запрос в одном gRPC-вызове, и потеря времени на дополнительный цикл обмена перевешивает любой потенциальный выигрыш от предварительной фильтрации в PostgreSQL.  
  Оптимизация стала бы заметной лишь при крайне высоких объёмах данных, но даже в таком случае добавленные задержка и сложность делают её плохим компромиссом для ожидаемого масштаба.

## Связанные решения
Отклонено в пользу [**ADR-004**](adr-004-hybrid-search.md) — гибридный поиск, полностью выполняемый внутри Qdrant с фильтрацией по payload.
