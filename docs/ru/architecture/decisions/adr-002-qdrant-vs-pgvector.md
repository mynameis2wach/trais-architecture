# ADR-002: Выбор Qdrant вместо PostgreSQL + pgvector

## Статус
Принято

## Контекст
Система генерирует несколько типов векторов для каждой встречи:
- множественные эмбеддинги чанков (размерностью 768+),
- один или несколько векторов саммари (до 1024 измерений).

При типичной нагрузке в десятки встреч в день общее число хранимых векторов быстро достигает сотен тысяч, а затем и миллионов.  
pgvector — это расширение PostgreSQL, не рассчитанное на такие объёмы высокоразмерных векторов; с ростом набора данных оно демонстрирует значительное падение производительности.

## Решение
Использовать специализированную векторную базу данных — **Qdrant**, которая изначально создана для хранения и поиска миллионов векторов с фильтрацией по payload.

## Последствия
- **Положительные**:
  - Высокая производительность и предсказуемая задержка запросов на масштабе.
  - Нативная поддержка нескольких векторов на точку естественно соответствует нашей модели данных (эмбеддинги чанков + векторы саммари, размещённые вместе с метаданными).
  - Тесная интеграция с подходом гибридного поиска (см. [ADR-004](adr-004-hybrid-search.md)).
- **Отрицательные**:
  - Дополнительная система баз данных, требующая поддержки и мониторинга (см. также [ADR-001](adr-001-split-storage.md) о разделении хранилищ).
  - Ещё одна технология в стеке, что повышает эксплуатационную сложность.
