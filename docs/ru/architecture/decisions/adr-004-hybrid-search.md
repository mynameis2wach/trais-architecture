# ADR-004: Гибридный поиск с фильтрацией на основе payload

## Статус
Принято

## Контекст
Пользователям необходимо искать историю встреч, сочетая семантическое понимание с точными фильтрами по датам, спикерам, длительности и другим метаданным. Задача состоит в том, чтобы выполнять это эффективно, без перемещения больших объёмов данных между сервисами.

## Решение
Выполнять **гибридный поиск непосредственно внутри Qdrant**: один запрос несёт и вектор запроса, и структурированные фильтры (условия на payload). Qdrant возвращает ранжированный список релевантных идентификаторов чанков или встреч за один шаг.

API Gateway формирует этот унифицированный запрос и никогда не выполняет отдельную фильтрацию в PostgreSQL (см. [ADR-001](adr-001-split-storage.md) и [ADR-003](adr-003-postgresql-prefiltering.md)).

## Последствия
- **Положительные**:
  - Максимальная производительность — фильтрация и ранжирование происходят в одном движке, исключая накладные расходы на передачу данных.
  - Простой код API — не требуется объединять результаты из разных баз данных.
- **Отрицательные**:
  - Логика фильтрации зависит от возможностей payload в Qdrant; для крайне сложных SQL-подобных фильтров может потребоваться постобработка.
  - Метаданные, необходимые для фильтрации, должны дублироваться в payload Qdrant, что несколько увеличивает потребление хранилища.
